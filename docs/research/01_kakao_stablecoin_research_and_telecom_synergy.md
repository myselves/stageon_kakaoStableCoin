# 카카오 원화 스테이블코인 사업 조사 및 통신 결합 시너지 의견

- 작성일: 2026-10-19
- 목적: "카카오 스테이블코인으로 매월 결제 가능한 통신서비스" 프로토타입의 사전 조사
- 주의: 2026-10-19 기준 원화 스테이블코인은 **법제화 전**이며, 카카오 코인은 **미발행** 상태. 아래 내용은 공개 보도 기반이며, 프로토타입은 모의 토큰(테스트넷)으로 설계해야 함.

### 1-2. 4단계 준비 전략
1. 발행
2. 유통 인프라
3. 사용자 채널 (카카오페이 지갑, 카카오톡)
4. 유즈케이스 (실제 사용처)

### 1-3. 공개된 유즈케이스 시연 (2026-09-28)
- 원화 스테이블코인 발행·상환
- 디지털 지갑 기반 송금·결제
- 외국인 인바운드 국내 결제 및 가맹점 정산
- **에이전틱 결제**: AI 에이전트가 사용자를 대신해 결제 수행 (x402 기반)

### 1-4. 생태계 전략
- 발행·유통을 소수가 독점하는 구조 대신 **개방형 라운드테이블** 제안 (은행·증권·핀테크·플랫폼·가상자산사업자·이커머스·콘텐츠).
- 경쟁의 무게중심이 "누가 먼저 발행하느냐"에서 "**누가 더 넓은 사용처를 확보하느냐**"로 이동 중. 통신요금은 전 국민 대상 월 고정 결제라는 점에서 사용처 확보 경쟁의 핵심 영역.

### 1-5. 수익 모델 (카카오뱅크 언급)
- 준비자산 운용에 따른 배당 수익
- 수탁(커스터디) 수수료
- 서비스(결제·정산) 수수료

### 1-6. 경쟁 구도
| 진영 | 구성 |
|---|---|
| 카카오 | 카카오뱅크 + 카카오페이 + 카이아 + KB국민은행 + 서클 |
| 네이버 | 네이버파이낸셜 + 두나무(업비트) 주식교환 추진 + 하나은행(두나무 지분 6.55%) |
| KT | KT(통신·보안) + 케이뱅크(은행) + BC카드(350만 가맹점 결제·정산), 계열사 PoC 진행 중 |

### 1-7. 규제 현황 (가장 큰 변수)
- 디지털자산기본법 정부안: 2026-10-08 국정감사에서 금융위원장 "막바지 협의". 9월 제출 목표를 넘겼고 11월 법안소위 논의 전망.
- 핵심 쟁점:
  - **발행 주체**: 은행 50%+1주 컨소시엄(한은 입장) vs 비은행 허용(금융위·핀테크 입장). 미확정.
  - **이자·리워드 금지 범위**: 발행인 이자 지급 금지는 공통. 일부 안은 거래소·취급사업자의 "일체의 재산적 가치 지급"까지 금지 → **보유 연동 리워드는 이자로 간주될 위험**. 결제·사용 연동 리워드 허용 여부가 변수.
  - 자본금 요건: 5억~250억 원 범위에서 이견.
- 수수료 경제(국회예산정책처): 카드 가맹점 수수료 1.3% vs 스테이블코인 0.3% 가정 시 연 0.37조~5.15조 원 절감 추정.

## 2. 통신 × 카카오 스테이블코인 시너지 의견

### 2-0. 전제: 스테이지파이브(핀다이렉트)의 현재 위치
- MVNO(이통 3사 망 전체 적용) + 로밍 사업 + 자체 AI 통신 플랫폼 '스테이지온(STAGE-ON)' (외부 기업도 통신 서비스를 설계·운영 가능).
- 이미 **남은 데이터 → 밀크코인 리워드** 요금제 운영 중. 2026-09-28 '더 브릿지 서밋 2026' 기조연설에서 리워드를 디지털 자산 지갑·결제에 연결하고 **스테이블코인 기반 결제·정산, RWA**로 확장하겠다고 발표.
- 즉, 통신 측 사용처(월 고정 결제, 데이터 마이크로 거래, 로밍, B2B 정산)와 카카오 측 인프라(지갑 4,300만, 카이아, 에이전틱 결제)가 맞물리는 지점이 시너지의 본체.

### 2-1. 시너지 영역 (우선순위 순)

#### A. 월정액 통신요금 자동결제 (프로토타입 코어) — 우선순위 1
- **구조**: 가입 시 사용자가 지갑에서 "월 n원 한도, 매월 d일" 결제 위임(allowance 또는 pull-payment 승인)을 1회 서명 → 청구일에 통신사 정산 컨트랙트가 스테이블코인을 인출 → 온체인 영수증 발행.
- **통신 측 이득**
  - MVNO는 ARPU가 2~3만 원대로 낮아 카드·PG 수수료(1% 초반+)가 마진에 직격. 0.3%대 결제 비용은 수익성 개선 요인.
  - 즉시 최종성(T+0) → 후불 미납·연체 리스크 축소, 추심 비용 절감.
  - 신용조회 없는 가입 가능 → 외국인·신용취약층·청소년 등 알뜰폰 핵심 고객군 확대. 사실상 "선불의 편의성 + 후불의 자동화".
- **카카오 측 이득**: 전 국민 월 고정 결제라는 가장 끈끈한 반복 사용처 확보. 지갑 활성 사용자(MAU) 고정.
- **설계 시 유의**: 잔액 부족·위임 철회 시 실패 처리(dunning, 카드/계좌 fallback), 청약철회·환불(온체인 환불 트랜잭션), 가스비 UX(가스 대납·계정추상화).

#### B. 데이터 ↔ 스테이블코인 양방향 교환 — 우선순위 2
- **데이터 → 코인**: 기존 "남은 데이터 → 밀크코인" 모델을 원화 스테이블코인(또는 포인트 → 스테이블코인 전환)으로 확장. 사용자는 통신비가 "줄어드는" 체감.
- **코인 → 데이터**: 데이터 쿠폰·부가서비스를 스테이블코인으로 즉시 소액 구매(마이크로 결제). 카드 최소 결제 금액·수수료 때문에 어려웠던 500~1,000원 단위 거래 가능.
- **규제 설계**: 보유량 연동 리워드는 "이자"로 간주될 위험이 큼. **사용량·결제 행위 연동 리워드**로 설계해야 안전.

#### C. 에이전틱 결제 (AI 에이전트 × 스테이지온) — 우선순위 3, 차별화 포인트
- 카카오가 시연한 x402 기반 에이전틱 결제와 스테이지온 AI 통신 플랫폼의 직접 결합.
- 시나리오: 에이전트가 사용 패턴을 분석 → 요금제 변경·데이터 추가 구매를 제안/실행 → 사용자가 설정한 한도 내에서 스테이블코인으로 자동 결제.
- 통신 API(요금제 변경, 데이터 충전, 로밍 개통)에 x402 결제 레이어를 붙이면 "AI가 결제까지 끝내는 통신"이라는 명확한 메시지 가능.

#### D. 로밍·인바운드 (카이아·라인 생태계 활용) — 우선순위 4
- 핀다이렉트 로밍 + 카카오의 인바운드 해외결제·정산 실증 + 카이아의 라인 생태계(일본 JPYC, 태국·대만) 연결.
- 외국인 관광객: 지갑의 스테이블코인으로 한국 eSIM·로밍 즉시 구매(카드 없이).
- 내국인 출국자: 원화 스테이블코인으로 해외 로밍 결제, 해외 통신사와의 정산도 스테이블코인으로.

#### E. B2B 정산 자동화 — 중기
- MVNO ↔ MNO 망 도매대가 정산, 유통점·제휴사 수수료 정산, 스테이지온 외부 고객사 정산을 스테이블코인으로 T+0 처리.
- 프로그래머블 스플릿(결제 즉시 망 대가·유통 수수료·플랫폼 수수료 자동 분배)으로 정산 운영비 절감.

#### F. 카카오톡 채널 결합 — 중기
- 알림톡 청구서 → 카카오페이 지갑 원터치 결제. 4,300만 지갑 사용자에게 통신 가입·결제 진입점 제공.

#### G. 본인확인·KYC 상호 보완 — 중기
- 통신사 본인확인 인프라와 지갑 KYC·AML(트래블룰) 연결. 통신사가 스테이블코인 지갑 온보딩의 신원 레이어 역할을 맡을 수 있음.

#### H. 토큰화·RWA — 장기
- 선불 요금 잔액, 단말 할부채권 등을 토큰화(스테이지파이브가 언급한 RWA 영역). 법제화 이후 검토.

### 2-2. 리스크와 대응
| 리스크 | 대응 |
|---|---|
| 법제화 지연·발행 주체 미확정 | 프로토타입은 체인·토큰을 추상화하여 어떤 발행사 코인이든 교체 가능하게 설계 |
| 카카오 코인 미발행 | 카이아 테스트넷(Kairos) + 모의 KRW 토큰(ERC-20 호환)으로 구현 |
| 보유 연동 리워드 = 이자 간주 가능성 | 리워드는 사용량·결제 연동으로만 설계 |
| 가스비·지갑 UX | 가스 대납, 계정추상화, 카카오페이 지갑 연동 전제 |
| 환불·청약철회 | 온체인 환불 트랜잭션 + 오프체인 원장 동기화 |
| 전자금융업·가상자산사업자 규제 | 프로토타입 단계에서는 결제 대행 구조를 가정하고 법무 검토 병행 |

## 3. 프로토타입 범위 제안 (1차)

1. **지갑 연결 & 결제 위임 승인**: 모의 KRW 스테이블코인 지갑 연결, 월 한도·결제일 1회 서명.
2. **월 청구 → 자동 인출 → 영수증**: 스케줄러가 청구일에 pull 결제, 온체인 영수증 + 앱 내 청구서.
3. **잔여 데이터 리워드**: 월말 잔여 데이터를 스테이블코인(또는 전환 가능 포인트)으로 적립.
4. **실패 처리**: 잔액 부족 시 알림 → 재시도 → fallback(카드/계좌) 모의 처리.
5. (선택) **에이전트 결제 데모**: 사용 패턴 기반 데이터 추가 구매를 한도 내 자동 결제.

기술 스택 가정: 카이아 테스트넷(Kairos), ERC-20 호환 모의 KRW 토큰, 구독 결제 컨트랙트(allowance 기반 pull), Node/Next.js 데모 앱, 오프체인 청구·원장 DB.

## 4. 프로토타입 구현용 프롬프트 초안

```
핀다이렉트(MVNO) 통신요금을 원화 스테이블코인으로 매월 자동결제하는 프로토타입을 만들어줘.
- 체인: 카이아 테스트넷(Kairos). 모의 KRW 스테이블코인(ERC-20 호환, 심볼 mKRW) 배포.
- 컨트랙트: 구독 결제(월 한도·결제일을 사용자가 1회 승인, 통신사 정산 컨트랙트가 매월 pull), 온체인 영수증 이벤트, 환불 함수.
- 앱: 요금제 선택 → 지갑 연결 → 결제 위임 승인 → 청구서/결제 내역 조회 → 잔여 데이터 리워드 적립 화면.
- 백엔드: 청구 스케줄러, 잔액 부족 시 재시도 및 fallback 플래그, 오프체인 원장 동기화.
- 리워드는 보유량이 아니라 사용량·결제 연동으로만 설계.
- 발행사·토큰은 교체 가능하도록 추상화.
```
